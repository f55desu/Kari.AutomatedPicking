# WB Отбор — инструкция для пользователя

Программа автоматически собирает **еженедельный отчёт**
«Отчёт WB о выбросах CTR, CR» по товарам на Wildberries:
подтягивает продажи и остатки из SQL, получает количество фото
по каждому артикулу, сохраняет итоговый Excel-файл и отправляет
его в Telegram.

---

## 1. Что у вас должно быть в папке

Создайте на своём ПК или сетевом диске папку (например, `C:\WB_Otbor`)
и положите в неё **все 5 файлов**, которые вам выдали:

```
C:\WB_Otbor\
├── wb_otbor_gui.exe         ← GUI: кнопки, настройки, планировщик
├── wb_otbor_runner.exe      ← консольный pipeline (для планировщика)
├── Отбор Шаблон.xlsx        ← шаблон итогового файла (формулы, стили)
├── .env                     ← токены WB API + Telegram (СЕКРЕТНЫЙ!)
└── USAGE.md                 ← этот файл
```

> **Важно:**
> - Все 5 файлов должны лежать **в одной папке**.
> - `.env` — секретный, там API-токены. Не копируйте его никуда наружу.
> - Путь к папке может быть любой: локальный (`C:\WB_Otbor`) или сетевой
>   (`\\kari.local\public\...\WB_Otbor`) — программа автоматически разберётся.

После первого запуска в той же папке появятся автоматически:

```
├── photo_cache.xlsx         ← кэш количества фото (обновляется сам)
├── settings.json            ← ваши настройки фильтров
├── logs\
│   └── wb_otbor.log         ← файл с журналом выполнения
└── Отчёт WB о выбросах CTR, CR на DD.MM.xlsx   ← результаты работы
```

## 2. Что нужно на вашем ПК

- **Windows 10 или 11**
- **ODBC Driver 17 for SQL Server** — если не установлен, скачайте и
  установите с сайта Microsoft:
  https://learn.microsoft.com/sql/connect/odbc/download-odbc-driver-for-sql-server
- Доступ к корпоративной сети Kari (к `cl01sql`).
  Удалённо — через VPN.
- Интернет для WB API и Telegram.

Python устанавливать **не нужно** — всё внутри exe.

## 3. Первый запуск

1. **Двойной клик** по файлу **`wb_otbor_gui.exe`**.
2. Откроется окно программы:

   ```
   ┌─ Ручной запуск ─────────────────────────────────────┐
   │ [▶ Запустить сейчас]  [Открыть папку]  [⚙ Настройки]│
   │ ☐ Использовать кэш фото                             │
   ├─ Сборка EXE ────────────────────────────────────────┤
   │ [🔨 Собрать EXE]  ← вам это не нужно, пропускайте    │
   ├─ Планировщик задач Windows ─────────────────────────┤
   │ Дни недели: ☑Пн ☐Вт ☐Ср ☐Чт ☐Пт ☐Сб ☐Вс            │
   │ Время: [09:00]   [Сохранить задачу] ...             │
   ├─ Журнал выполнения ─────────────────────────────────┤
   │ ... тут бежит лог работы                            │
   └─────────────────────────────────────────────────────┘
   ```

3. **Нажмите «⚙ Настройки»**. Откроется окно фильтров.
4. В окне настроек нажмите **«🔄 Получить уникальные значения
   параметров из БД»**. Программа скачает списки групп, брендов,
   сезонов и т.д. из справочника. Надпись справа изменится на
   «Кэш обновлён: YYYY-MM-DD HH:MM:SS».
5. Выберите нужные значения в фильтрах (см. §6) и нажмите
   **«Применить параметры»**.
6. Закройте окно настроек.
7. Нажмите **«▶ Запустить сейчас»**.

Первый прогон занимает **5–15 минут** (долгая стадия —
получение количества фото через WB API). В журнале внизу
увидите этапы: SQL → WB API → Excel → Telegram.

По завершении:
- В папке появится файл `Отчёт WB о выбросах CTR, CR на DD.MM.xlsx`.
- Этот же файл придёт в Telegram (получатели указаны в `.env`).

## 4. Повторные запуски (с кэшем)

Если запускаете отчёт второй раз в тот же день / сразу после
первого прогона:

1. Поставьте галочку **☑ «Использовать кэш фото»**.
2. Нажмите **«▶ Запустить сейчас»**.

Программа прочитает количество фото из файла `photo_cache.xlsx`
и не будет обращаться к WB API. Отчёт соберётся за **10–30 секунд**.

> Кэш обновляется автоматически при каждом обращении к WB API,
> даже если галочка стояла. Удалять `photo_cache.xlsx` вручную не нужно.

## 5. Автоматический запуск (раз в неделю)

Чтобы программа собирала отчёт сама по расписанию:

1. В секции **«Планировщик задач Windows»** отметьте дни недели
   (например, только `Пн`).
2. Задайте время в формате `HH:MM` (например, `09:00`).
3. Если хотите ускорить автозапуск за счёт кэша фото —
   отметьте **☐ «Задача запускает с --use-cache»**
   (в обычных запусках по расписанию это не рекомендуется —
   лучше свежие данные).
4. Нажмите **«Сохранить задачу»**.
5. В окне подтверждения нажмите «ОК». Появится статус:
   `✓ включена | расписание: Еженедельно @ 09:00:00`.

Всё. Теперь каждый понедельник в 09:00 Windows сам запустит
`wb_otbor_runner.exe` (консольный exe — тот самый второй файл,
который вам выдали). Файл соберётся и улетит в Telegram без
вашего участия.

**Управление задачей:**

| Кнопка | Что делает |
|--------|-----------|
| **Включить** | Возобновить задачу после «Отключить» |
| **Отключить** | Временно приостановить (без удаления) |
| **Удалить задачу** | Совсем убрать из планировщика |
| **⟳ Обновить статус** | Перечитать текущее состояние |

> Если ПК выключен в момент запланированного времени — задача
> пропустится. Windows может запустить её при следующем включении,
> если это настроено в планировщике. Рекомендую оставлять ПК
> включённым в день запуска.

## 6. Настройки (окно «⚙ Настройки»)

### Фильтры справочника

Семь категорий товаров из справочника Kari. В каждой — список
значений, которые можно **выбрать** (multi-select):

- **Бизнес-группа** (например, «Одежда для детей», «Одежда и аксессуары»)
- **Розничный отдел**
- **Группа** (3-значный код + название, например `072 Трусы женские`)
- **Сезон**
- **Бренд**
- **Ответственный за группу** (ФИО менеджера)
- **Коллекция** (например `2026SS`)

Правила выбора:
- **Ctrl + клик** — добавить/убрать значение в выделении
- **Shift + клик** — выделить диапазон
- **«Выделить всё»** — все значения этого фильтра
- **«Снять выделение»** — пустой фильтр = **фильтр не применяется**,
  в отчёт попадают все значения этой колонки

> Сверху окна показывается строка **«Текущий выбор»** — всегда видно,
> что сейчас задано.

### Числовые параметры (справа)

| Параметр | По умолчанию | Что делает |
|----------|--------------|------------|
| Длина периода, дней | 7 | Отчёт охватывает сток+маркетинг за N дней |
| Сдвиг от сегодня, дней | 1 | Конец периода = сегодня − N (т.к. данные WB приходят с задержкой) |
| Мин. остаток, шт. | 10 | Ниже → артикул получает метку «Мало остатка» |
| Мин. дистрибуция, % | 20 | Ниже → тоже «Мало остатка» |
| Мин. показы | 1200 | Ниже → артикул получает метку «Мало показов» |

После изменений — **«Применить параметры»**. Настройки сохранятся
в файл `settings.json` рядом с exe-файлами.

Кнопка **«Сбросить к дефолтам»** вернёт заводские значения.

### Как часто обновлять справочник

Раз в пару месяцев — когда появляются новые коллекции, бренды,
менеджеры. Нажать «🔄 Получить уникальные значения из БД» в окне
настроек.

## 7. Итоговый Excel-файл

`Отчёт WB о выбросах CTR, CR на DD.MM.xlsx` содержит **два листа**:

### Лист 1 — основной

Таблица по артикулам, отсортирована по **Показам по убыванию**.
Столбцы: Артикул, Артикул WB, Бизнес-группа, Отдел, Группа, Сезон,
Бренд, Ответственный, Коллекция, **Показы / Клики / Заказы / CTR / CR**,
Остаток, Дистрибуция, **Техничка** (1 = хороший артикул, 0 = отсеян),
Отбор для поиска / по CTR / по CR (и то же «внутри группы»),
Количество фото (−2 от фактического).

### Лист 2 — «Применённые фильтры»

Для аудита/воспроизводимости: на каких настройках собран отчёт
(период, все значения фильтров, пороги Технички, дата формирования).

## 8. Решение частых проблем

### «Ошибка SQL» / «Нет подключения к cl01sql»

- Проверьте, что вы в сети Kari (на рабочем ПК — через Wi-Fi/LAN,
  удалённо — через VPN).
- Попробуйте открыть через проводник `\\cl01sql\...` — должно пускать.
- Если не пускает — обратитесь в IT-поддержку Kari.

### «Не найден токен WB API»

Файла `.env` нет рядом с exe или он повреждён. Проверьте, что файл
лежит **в той же папке, что и exe-файлы**, и внутри есть строка:
```
WB_API_TOKEN = eyJ...
```

### «В списках фильтров пусто»

Вы ещё не обновили справочник. Откройте «⚙ Настройки» → нажмите
**«🔄 Получить уникальные значения параметров из БД»**.

### Файл создан, но не пришёл в Telegram

- Откройте `logs\wb_otbor.log`, найдите строку с `Telegram`.
- Скорее всего, прокси не смог пробиться (корпоративная сеть блокирует
  telegram). Файл на диске есть — отправьте его в Telegram вручную.

### Задача в планировщике не сработала

1. Откройте **Планировщик заданий Windows** (`taskschd.msc`).
2. Найдите задачу **`WB_Otbor_AutoRun`**.
3. Вкладка **«Журнал»** — посмотрите код ошибки.
4. Если пишет «Не удаётся найти указанный файл» —
   откройте задачу, вкладка **«Действия»** → там путь.
   Если путь начинается с `\\fs05\...` вместо
   `\\kari.local\public\...`, то:
   - Откройте `wb_otbor_gui.exe`
   - Нажмите **«Сохранить задачу»** заново — программа автоматически
     подменит путь на правильный.

### Статус задачи всегда «отключена»

Нажмите **«⟳ Обновить статус»**. Если не помогло — откройте задачу
в Планировщике заданий Windows и убедитесь, что она действительно
включена («Состояние: Готова»).

### Окно с кнопкой «🔨 Собрать EXE» выдаёт ошибку

Игнорируйте эту кнопку — она нужна только разработчику. У вас уже
есть готовые exe-файлы, пересобирать не надо.

### Где посмотреть детали ошибки

Все события пишутся в файл **`logs\wb_otbor.log`**. Откройте его
любым текстовым редактором (Блокнот, VSCode). Последние строки —
самая свежая активность. Если непонятно — пришлите этот файл
разработчику.

## 9. Частые сценарии работы

### Хочу разовый отчёт прямо сейчас по всем товарам 2026SS

1. `wb_otbor_gui.exe` → «⚙ Настройки»
2. В фильтре **Коллекция** выделите `2026SS`, остальные оставьте пустыми.
3. «Применить параметры»
4. «▶ Запустить сейчас»

### Хочу отчёт только по одной бизнес-группе

1. «⚙ Настройки» → в фильтре **Бизнес-группа** выделите одну
   (например, «Одежда и аксессуары»), остальные фильтры очистите.
2. «Применить параметры» → «▶ Запустить сейчас»

### Хочу настроить автоматический еженедельный отчёт

1. «⚙ Настройки» → выберите свои фильтры → «Применить параметры»
2. В главном окне: дни = «Пн», время = `09:00` → «Сохранить задачу»
3. Убедитесь, что `✓ включена`.

Готово. Каждый понедельник в 09:00 отчёт придёт вам в Telegram.

### Что-то пошло не так

1. Откройте `logs\wb_otbor.log`
2. Найдите строку с `ERROR` или `FAIL`
3. Пришлите последние 100 строк разработчику.
